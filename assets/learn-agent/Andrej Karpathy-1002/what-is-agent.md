从项目资料助手看：下一步查什么，取决于已查到什么。

## A 核心定义
```callout info 本文讨论 LLM Agent
模型选择下一步，应用执行工具。结果返回模型，影响后续选择。
```

目标、观察、行动、反馈，共同推动任务。

[阅读 Tyron 原文](https://tyron.me/posts/what-is-agent)

## B 决策与执行循环 {span=2}
```flow LR
(任务) -> *模型选择
模型选择 -> 应用执行: 工具请求
应用执行 -> 工具反馈
工具反馈 -> 模型选择: 更新上下文
模型选择 -> (回答或追问): 判断资料是否足够
```

订单文档引用公共分页规范，助手据此继续读取规范。

## C 谁决定下一步 {span=2}
| 方式 | 下一步如何确定 |
| --- | --- |
| 普通问答 | 用户给资料，模型解释后结束 |
| Workflow | 程序预设步骤和分支 |
| Agent | 模型根据任务状态和反馈参与选择 |

聊天界面、工具和循环，本身不能区分这三种方式。

## D 常见误区
| 能力 | 负责什么 |
| --- | --- |
| RAG | 提供回答依据 |
| 记忆 | 保存并取回信息 |
| MCP | 接入外部能力 |
| Skills | 提供任务指引 |

这些能力均不能单独等同于 Agent。

```callout warn 工具成功 ≠ 任务成功
仍需核对依据、版本、权限和停止条件。达到限制而结束，不能算完成。
```
