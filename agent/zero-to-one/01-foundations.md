# 01｜先知道 Agent 到底在做什么

[返回总入口](README.md) · [下一课：工具循环](02-agent-loop-lab.md)

## 1. 先用一个问题区分四种系统

假设你问：“我会 Java，想学习 Agent。请根据这个项目给我安排三天学习任务，并指出资料位置。”

| 系统 | 它可能怎样工作 | 你要检查什么 |
|---|---|---|
| 普通聊天 | 根据已有知识生成一段学习建议 | 它是否真的看过这个项目 |
| RAG 问答 | 检索项目文档，再根据片段回答 | 检索片段是否相关、答案是否有依据 |
| 固定工作流 | 按预设顺序读取目录、检索、生成计划 | 顺序能否覆盖任务，失败如何退出 |
| LLM Agent | 根据目标和工具返回，选择继续检索、读取、追问或回答 | 动作是否有效，何时结束，权限是否受控 |

本课程讨论的是 LLM 驱动的 Agent：模型参与选择下一步，程序把动作落实到工具，并把结果带回后续决策。不同资料对 Agent 的定义宽窄不一，不必纠缠名称；看决策权在哪、执行边界在哪。

固定工作流也可以调用模型。RAG 也可以成为 Agent 的一个工具。一次任务用了多个步骤，不自动说明它是多 Agent。

这组区分借鉴 [Anthropic 对 workflows 和 agents 的说明](https://www.anthropic.com/engineering/building-effective-agents)；上面的资料助手是本课程自拟案例。

## 2. 只记住这几个词

| 词 | 白话解释 | 在资料助手中是什么 |
|---|---|---|
| LLM / 模型 | 根据输入生成输出的模型 | 理解问题，提出下一步动作，组织答案 |
| Prompt / 提示词 | 交给模型的任务与要求 | “只根据读到的资料回答，附上出处” |
| Token | 模型处理文字的单位，不能简单等同一个汉字 | 输入和输出都会占用上下文及可能的计费额度 |
| API | 程序调用另一个服务的接口 | Java 把消息发给模型服务 |
| SDK | 封装 API 的开发工具包 | 帮你构造请求、解析响应 |
| Tool / 工具 | 程序提供的明确能力 | 搜索文档、读取指定资料 |
| Tool Call | 模型提出的结构化调用请求 | “调用 search_notes，关键词为 RAG” |
| Tool Result | 工具执行后的数据或错误 | “找到 study-notes/rag.md”或“没有匹配项” |
| Agent Loop | 决策、执行、观察、再决策的循环 | 先查目录，再读资料，最后回答 |
| Context / 上下文 | 这一次模型调用真正看到的信息 | 任务、工具说明、选中的历史和资料片段 |
| State / 状态 | 程序保存的任务进度 | 已读哪些资料、剩余几步、是否取消 |
| Session / 会话 | 一组连续交互及其身份边界 | 当前用户这次学习咨询 |
| Memory / 记忆 | 为后续使用保留的信息 | 经用户确认的学习目标与进度 |
| Harness | 管理 Agent 运行的外围软件 | 限制工具、保存状态、处理取消、记录轨迹 |
| Eval / 评测 | 用固定问题检查结果 | 十道题，统计证据正确率和失败处理 |

“记忆”不代表模型自己修改了参数。把学习偏好保存到文件，下次再读入，也可以构成一种外部记忆机制。

## 3. 谁决定，谁执行，谁负责

以搜索资料为例：

1. 开发者提供工具名字、用途、参数规则和权限。
2. 模型提出 `search_notes` 调用，参数为 `{"query":"RAG"}`。
3. 运行程序检查工具是否允许、参数是否合规。
4. 工具真正搜索资料，返回命中文档或错误。
5. 程序将结果与这次调用关联，交给模型。
6. 模型继续提出动作或给最终回答；程序执行总步数等硬限制。

**模型说“已经搜索”不是执行证据。** 必须有实际工具返回。模型输出看似正确的 JSON，也不意味着参数有效或操作已获授权。工具调用的一般过程可对照 [OpenAI 官方说明](https://developers.openai.com/tracks/building-agents)。

可以把模型理解成“提出下一步的成员”，工具是“能实际办事的程序”，Harness 是“管理权限、记录和进度的执行环境”。这个类比用于分工，不能据此认为模型像真人一样可靠。

## 4. 不写代码的第一堂实验

准备纸和笔，或一个普通文本文件。模拟用户、模型和工具三个角色。

任务：在三条虚构学习资料中找到 Java Agent 的入口。

可用资料：

- `LLM → study-notes/llm.md`
- `RAG → study-notes/rag.md`
- `Java → study-notes/java-agent.md`

第一轮，“模型”只能写下面两种格式之一：

```text
调用：search_notes(query="Java")
回答：……
```

“工具”从上面的三条资料查找，回复 `study-notes/java-agent.md`。第二轮“模型”才能把这个位置组织成答案。请把每一轮的输入、动作、结果写出来。

现在把任务改成“找到 Kubernetes 的学习入口”。工具应返回“无匹配”，最后答案应说明当前资料不足。不能为了完成任务擅自编一个路径。

再做一次：工具返回“暂时读取失败”。此时应区分“查不到资料”和“工具没有正常工作”。同样没有答案，却是两类不同问题。

**验收**：你能指出哪行是调用请求、哪行是执行结果，并能说明工具报错后为什么不能声称“已查阅”。

## 5. 提示词先写任务契约

新手常写“你是世界顶级 Agent 专家”，却没有说明输出怎样才算完成。可以改成：

```text
任务：根据提供的学习资料，为会 Java 的初学者安排三天 Agent 学习。
可用信息：用户提供的资料和实际工具返回。
输出：每天一个目标、一个练习、一个验收条件，并标注来源路径。
资料不足：明确写出缺少什么，不编造目录、API 或视频内容。
边界：只读取允许的学习资料，不修改文件，不访问密钥和业务数据。
```

这只是交给模型的说明；允许读取哪些文件、能否执行工具，仍要由程序约束。

如果使用 AI 辅导自己，追加：“先给我一个小问题，等我解释后再提示；不要直接替我完成练习。”让 AI 帮你发现盲点，而不是只替你生成学习记录。

## 6. 第一周先不学什么

先不推导完整 Transformer，不部署向量数据库，不接多个框架，不做自主改代码，不复现大型多 Agent 系统。遇到一个名词先问：它解决我的哪个已出现的问题？

比如三篇 Markdown 已经能靠关键词查到，先用关键词检索建立基线。以后测试发现“检索增强生成”查不到写着“RAG”的资料，再尝试同义词或向量检索，并比较结果。

## 课后检查

1. 工具返回“没有找到”，模型能否据此说“项目没有任何相关资料”？为什么？
2. 一条固定的“检索 → 总结”流水线为什么也可能满足需求？
3. 为什么“请不要越权”不能替代工具执行前的权限检查？
