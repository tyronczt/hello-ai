## 实际生成提示词

### 图 1

为中文 Java Agent 教程生成一张 16:9 横版解释插画，输出 PNG。实际参考图只用于人物身份与温暖手绘画风，不复制九宫格。米白纸纹背景，深色清晰线条，柔和蓝绿，少量暖橙，充足留白，中文字必须清晰准确。画面解释“提示词引导决策，Java 校验执行”。左上是一张蓝色任务说明纸，短标签“目标 / 流程 / 示例”；左下是一份绿色数据纸，短标签“工具事实”。这两份纸用清晰箭头进入中央小显示屏，显示屏只标“模型”，屏右输出一张请求纸，标“工具请求”。请求纸通过右侧一座橙色小闸门，闸门标“Java 校验”，闸门旁两个短标签“参数”“权限”；闸门之后右上是工具箱标“执行工具”，一条淡绿色反馈线从工具箱返回左下的“工具事实”，反馈线标“返回结果”。闸门右下另有一个明确分支，橙色拒绝印章标“拒绝”，分支在此结束，不连工具箱。底部单独一行短句“提示词引导选择，程序决定能否执行”。一位小天在闸门旁认真核对请求纸，约占画高 30%，不遮字、不代替模型执行流程。小天身份严格依据输入参考：深棕微乱短发、猫耳、黑圆框眼镜、深蓝卫衣、米色咖啡杯齿轮徽记、深灰工装裤和运动鞋、自身左腕装置、无尾巴、三头身、自然短颈。不要增加角色、排名、百分比、成功率或任何多余文字。准确的箭头和边界比装饰重要。这是概念示意，不是真实系统截图。

### 图 2

为中文 Java Agent 教程生成一张 16:9 横版解释插画 PNG。实际参考图只用于小天人物身份，不复制九宫格。米白纸纹、温暖手绘、清晰深色线条、柔和蓝绿与少量暖橙，大字短标签、留白充足。画面是一个提示词对照实验工作台。左侧有一个上锁的资料盒，内有四个整齐文件页，分别标“同一任务”“同一模型”“同一参数”“同一快照”；资料盒下方小字“固定条件”。从盒子分出两条清晰箭头到中间并排的两个试验盘，上方分别标“提示词 A”“提示词 B”，盘子相同，提示词纸的颜色不同。两盘各输出一叠观察记录，都汇合到右侧一份核对表，标题“逐项核对”，表中只有“地点”“日期”“未知值”“来源”四行方形空框，空框不打勾也不打叉，不提供虚构结果。下方再有短句“重复运行，保留失败”。画面底部一行醒目的总结“先看证据，再比较效果”。一位小天站在右侧核对表旁，用手将来自 A 与 B 的两张轨迹纸对齐，目光看纸，约占画高 30%，不遮标签。人物严格保持参考身份：深棕乱短发、猫耳、黑圆框眼镜、自然棕眼、深蓝卫衣和米色咖啡杯齿轮徽记、深灰工装裤运动鞋、自身左腕装置、无尾巴、自然短颈、三头身。不要奖杯、胜负标志、百分比、柱状结果图、多余角色；这张图只讲控制变量和证据核对，不能暗示 B 比 A 好。所有中文准确。

## 视觉检查

- 通过：两图横版、米白纸纹、蓝绿与暖橙、中文短标签清晰，正文按邻近概念插入。
- 通过：猫耳、棕发、圆眼镜、深蓝卫衣、咖啡杯齿轮徽记与自身左腕装置保持一致；短颈连接自然。第二图人物较大，仍未遮住核验项。
- 通过：第一图模型请求与程序执行分开，有拒绝出口；正文图注补充直接回答、停止与预算条件，并说明通用权限含义。
- 通过：第二图 A、B 共享固定条件并各自保留记录，核对框留空，没有暗示获胜者。
- 通过：在 900px 正文宽度的浏览器预览中查看两图与图注，中文可读、无图片裁切；思考题参考答案可展开并保持列表格式。
- 范围限制：图片是机制示意，不是完整时序或系统截图；第一图没有展开拒绝后的应用报告过程。人物为本次生成结果，尚未取得用户逐张认可，不宣称精确身份相似度。
