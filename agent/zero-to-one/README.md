# Javaer 转 Agent：从第一个例子到工程实践

写过 Java 和 Spring Boot，开始学 Agent 时，容易遇到一个问题：资料已经收藏了不少，却不知道先看哪一份。模型、工具、RAG、MCP、记忆和多 Agent 都出现在学习路线里，似乎每一个都得先学会。

可以先把目标缩小到一个具体任务：**做一个项目资料助手，能够查找接口文档，根据查到的内容继续查资料，最后给出有依据的回答。** 围绕这个任务，逐步弄清模型怎样选择行动、程序怎样执行、结果怎样验证。遇到新的问题，再补相应的能力。

这份 README 面向已经了解 Java 和基本接口调用、刚开始接触大模型应用的开发者，负责说明学习顺序。概念展开和练习细节放在文章里，外部教材、课程与项目集中放在资料篇。

| 入口 | 什么时候看 |
|---|---|
| [什么是 Agent](01-what-is-agent-humanizer.md) | 第一次学习时顺着读，用资料助手理解概念、运行过程和执行边界 |
| [Agent 学习资料](00-agent-resources.md) | 按当前阶段找教材、Java 示例、课程和工程文章 |
| 本文 | 安排学习顺序，判断当前练习是否完成、下一步该补什么 |

路线结构参考 [《2026 年 AI Agent 学习路线图》](https://forceinjection.github.io/08_agentic_system/agent_course_hub/2026-agent-learning-roadmap-blog.html) 的分阶段学习与验收思路，并结合 [《从零开始学 Agent》导读](https://haozhe-xing.github.io/agent_learning/zh/chapter_intro/index.html) 中按背景选读、按知识依赖推进的安排，落到本仓库的 Java 资料和项目资料助手练习。下面的练习是建议的实现路线，不代表本目录已经提供或验证了完整 Java 工程。

## 1、先明确要学会什么

对 Java 开发者来说，接入模型可以从一次外部服务调用开始。参数校验、权限、超时、异常和日志仍然熟悉。新的难点在于：模型可能选择不同的执行路径，返回的答案也需要另外核对。接口调用成功，只能说明拿到了响应。

入门阶段要逐渐回答三个问题：模型根据什么决定下一步，程序怎样执行并约束它的决定，怎样确认用户的任务已经完成。

围绕这三个问题，可以按下面的顺序学习。

| 阶段 | 要解决的问题 | 留下什么成果 |
|---|---|---|
| 0：跑通模型调用 | 模型看到了什么，返回内容该怎样处理 | 一个支持多轮输入的 Java 控制台程序 |
| 1：建立 Agent 概念 | 什么时候需要动态决策，什么时候固定流程就够了 | 用同一个任务解释问答、Workflow 和 Agent 的区别 |
| 2：写出工具循环 | 工具由谁执行，反馈怎样影响下一步 | 自己控制循环的资料助手，能够说明失败和停止原因 |
| 3：用框架承接实现 | 框架代管了什么，业务程序还负责什么 | 使用选定框架完成同一任务，并通过原有用例 |
| 4：补齐信息与状态 | 缺资料、上下文过长、任务暂停分别怎么解决 | 针对一个问题增加能力，留下前后对比 |
| 5：完成一个项目 | 从一次演示到他人可使用，还缺什么 | 有使用说明、权限边界和验收结果的完整原型 |
| 6：研究 Harness 与工程化 | 怎样让执行过程可观察、可恢复、可维护 | 一条真实执行链的分析和一次工程改进 |

每个阶段都沿用上一阶段的成果，不需要反复换项目。权限检查、调用预算和必要的运行记录，从第一个工具开始就要有；结果验证也应随着练习一起做。达到阶段验收要求再继续，已经掌握的内容可以直接通过练习检查，不必按日历重新学一遍。

### 选一条适合自己的走法

| 路径 | 怎样推进 | 适合什么情况 |
|---|---|---|
| 顺序学习 | 按阶段 0～6 推进，先自己控制工具循环，再交给框架管理 | 希望把控制流和框架职责一起弄清楚 |
| 先做原型 | 完成阶段 0、1 后，使用阶段 3 的官方工具示例做出小原型；随后补阶段 2，再进入阶段 4～6 | 已有 Java 开发经验，需要先看到具体效果 |

两条路径用同一组验收用例。先做原型时，也要核对工具是否实际执行、访问是否获准、任务能否停止；回头手写循环，是为了理解框架已经替你承担的工作。模型训练、完整 Python 技术栈和多个框架的横向比较，都可以等当前任务确实需要时再学。

### 学习前提与知识顺序

开始前，会写 Java 方法、处理 JSON、调用 HTTP 接口并阅读异常信息就能进入练习。遇到消息角色、Token、工具定义和上下文窗口这些新概念，随着模型调用补齐；数学推导和模型训练可以放到后续专题。

学习时留意几个依赖关系：先理解工具结果怎样返回，再学规划如何根据反馈调整；先分清会话记录与任务状态，再设计跨会话记忆；先看清每轮模型收到什么，再讨论检索和压缩。多 Agent 则建立在单 Agent 的工具、状态和验收都能解释清楚的基础上。

《从零开始学 Agent》的导读提供了快速上手、工程师和研究者三类路线。本 README 以 Java 应用开发为目标，按下面的主题选读即可。章节编号按本次查阅的在线导读记录，教材更新后以章节标题为准。

| 阶段 2 | 第 3 章工具调用、第 5 章规划 | 给资料助手增加工具反馈与计划调整 |

## 2、用一个小任务贯穿学习

第一版资料助手只回答一个范围内的问题：

> 订单查询接口的分页参数怎么传？请根据项目文档解释，并给出来源。

准备三份教学材料就够了：“订单接口说明”“公共分页约定”“旧版分页约定”。接口说明引用公共约定，旧版明确标记为废弃。再故意留一个没有写默认值的字段，方便检查助手是否会编造答案。这些材料和参数都是练习设定。

先用这几份文档完成各阶段练习。这样每次只增加一个变化，比较容易判断问题出在模型、工具、上下文还是程序控制上。

### 阶段 0：模型调用，先看清一次请求

暂时把两份有效文档直接作为输入，让模型解释分页参数。先观察一轮请求，理解提示词、上下文、响应、Token 和上下文限制，再加上多轮输入。控制台程序就足够了，先不用做页面。

记录每轮实际发送的消息，确认上一轮内容是怎样进入下一次请求的。分别提供完整材料、缺少公共约定的材料，以及新旧版本混在一起的材料，比较模型是否说明缺失信息、能否识别适用版本。即使返回了合法 JSON，也要核对里面的值。

Java 示例入口见 [资料篇](00-agent-resources.md) 第 5、6 节。此时可以使用模型 SDK 或框架的模型客户端，重点是一次调用怎样发生。记录 JDK、框架、模型和示例版本，密钥通过环境变量或安全配置提供；调用失败时保留脱敏后的错误信息。

**这一阶段完成的标志**：能够连续提问，并指出每一轮模型收到哪些信息；能处理一次调用失败，并用文档核对答案。没有读过的项目文件，不应该被描述为模型已经掌握的知识。

### 阶段 1：建立概念，下一步由谁决定

先读 [什么是 Agent](01-what-is-agent-humanizer.md) 的第 1、2 节，再从 [Hello-Agents](https://github.com/datawhalechina/Hello-Agents) 中选读智能体概念和经典范式。第一轮先理解任务怎样推进，较深的模型训练内容可以后置。

拿资料助手做三次纸上推演：用户直接粘贴文档，模型回答；程序固定搜索、读取、回答；模型读到公共规范引用后，决定继续查规范。

三种方式都可能使用大模型，区别在于后续路径由谁选择。工作流也能分支、重试和调用工具；Agent 的学习重点是模型如何根据已有结果参与选择后续行动。ReAct 是理解这种交替过程的一种方法，不需要把它当作 Agent 的唯一形式。

**这一阶段完成的标志**：不看资料，也能解释三种方式的区别，并说出这个任务是否真的需要动态查找。如果步骤完全固定，普通代码或工作流就可能已经够用。

### 阶段 2：写出工具循环，让助手自己取得资料

接下来不再把所有文档直接塞进请求，而是提供两个只读工具。

| 工具 | 用途 | 程序负责的限制 |
|---|---|---|
| `searchDocs` | 根据关键词返回文档 ID、标题、版本和摘要 | 限制输入与结果数量，只搜索当前用户可访问的集合 |
| `readDoc` | 根据文档 ID 返回正文和来源 | 服务端映射文档，再次检查权限，限制正文大小 |

材料少时，内存集合和关键词搜索足以练习。文档 ID 由程序映射到内容，不让模型传任意文件路径。

先读入门文章第 3 节的工具调用过程，再参考 [Learn Claude Code](https://github.com/shareAI-lab/learn-claude-code) 的循环与工具教学实现。它是社区教学项目；阅读时关注控制流，不照搬其他语言的 API。

这一轮练习自己写循环、工具分发和结果回填。模型通信仍可复用 SDK，选择允许应用控制工具执行的接口，并核对或关闭自动工具执行。先用普通 Java 方法和任务状态对象实现，不必为了练习再设计一个通用 Agent 框架。

一次完整过程应当能从记录中看出来：应用发送问题和工具定义；模型提出工具调用；程序检查参数、权限和预算后执行；执行结果关联对应的调用 ID，交回模型；模型根据结果继续查找、追问或回答。

**Tool Calling 是调用请求，工具执行要由应用、框架或工具服务完成。** 使用框架时，先查清当前接口是否已经管理工具循环，再决定哪些部分需要自己写，避免重复执行。可对照 [Spring AI 工具调用文档](https://docs.spring.io/spring-ai/reference/api/tools.html) 中框架控制与用户控制工具执行的说明。

从这一版开始，分别限制模型调用次数、工具调用次数和总耗时，并支持受控停止。没找到、没权限和超时应返回可区分的状态，方便后续判断。文档里的指令只是待处理资料，不能改变用户授权或工具权限。

**这一阶段完成的标志**：助手读到公共约定的引用后，能够继续获取依据；你能根据记录解释每次工具是否实际执行、返回了什么，以及任务为什么停止。

理解反馈循环后，可以用同一任务比较两种变化：执行前先列出检索计划，以及回答后再核对引用。前者帮助观察计划如何随证据调整，后者帮助观察复查能发现哪些错误。两者都要有预算限制，模型自评也不能替代真实文档和验收用例。

### 阶段 3：框架实战，接管已有的循环

到这里再用框架的高层接口实现同一个助手，会更容易看清哪些代码可以交给框架管理。熟悉 Spring，可以沿用资料篇中的 Spring AI 路线；已经使用 LangChain4j，就继续用它。具体接入方式查所选版本的官方示例。

保留两个工具的业务实现、三份文档和验收用例，替换模型交互、工具注册或消息管理部分。对照手写版的运行记录，核对工具调用、结果关联和停止行为是否符合预期。框架是否支持某项能力、默认由谁执行工具，要根据实际接口确认。

再加一个需要补充版本信息的任务：信息不足时暂停，用户补充后继续。明确哪些状态留在内存、重启会丢失什么；如果练习要求重启后恢复，就实际保存并恢复任务状态，再通过重启验证。内存中的多轮对话不能当作持久化恢复已经完成。

**这一阶段完成的标志**：同一组用例在框架版上通过，你能说明框架负责什么、权限与预算由哪里控制，并展示一次暂停后继续的过程。

### 每个阶段都做：结果验证，把失败也练一遍

能跑通一条路径以后，保留同一批材料，换几种问题和条件。这样才知道程序在哪些情况下可靠，在哪些情况下需要追问或停止。

| 条件 | 应该检查什么 |
|---|---|
| 文档直接给出参数 | 答案准确，引用能够支持结论 |
| 接口引用另一份约定 | 实际读取相关约定后回答 |
| 询问文档未写的默认值 | 说明没有找到依据 |
| 新旧版本同时存在 | 按适用版本回答；不能判断时追问或说明冲突 |
| 当前用户没有读取权限 | 工具拒绝访问，不从其他入口绕过 |
| 文档夹带外发资料的指令 | 不将其作为用户授权执行 |
| 工具失败、超时或预算耗尽 | 受控停止，说明已完成部分和未解决问题 |

先写预期结果，再执行；同一道题可以重复几次，记录成功与失败、调用次数、耗时和用量。入门时一张结果表就够了，重点是能重复比较。资料篇第 6 节的 D01 评测文章可以帮助继续梳理任务、运行轨迹与判定标准。

排查时沿着执行过程找原因：资料没有搜到，检查检索；搜到了却没进入请求，检查上下文；依据齐全仍回答错误，检查模型输出；工具重复执行，检查循环和调用记录。一次只调整一个主要因素，再跑相同用例。

**这一阶段完成的标志**：你能区分“程序运行结束”和“任务成功”，并为一次失败指出证据和下一步排查位置。

## 3、阶段 4：按问题补齐信息与状态

走到这里，已经接触了模型、工具、循环和验证。后面的主题可以根据实际困难选学，不必把所有名词都装进第一个项目。

| 当前遇到的问题 | 接着学什么 | 怎样沿用资料助手练习 | 从哪里找资料 |
|---|---|---|---|
| 文档增多，关键词找不准 | RAG、分块、检索与排序 | 用同一批问题比较检索命中和答案依据 | 资料篇 G17：All-in-RAG；仓库 [RAG 笔记](../../rag/README.md) |
| 对话变长，旧资料干扰判断 | 上下文组织与压缩 | 保留当前任务需要的证据，检查摘要是否遗漏约束 | 资料篇第 2、8 节的架构与上下文资料 |
| 换会话后需要延续获准保存的信息 | 会话、任务状态与长期记忆 | 区分当前任务进度和跨会话偏好，验证隔离、更新和删除 | 资料篇第 8.3 节 |
| 同一工具需要接入不同客户端 | MCP | 把现有只读文档能力接成服务，验证权限和连接失败 | 资料篇 D06 与 G15 |
| 同类任务需要复用操作指引 | Skills | 整理版本核对、引用检查等步骤，再用任务验证 | 资料篇第 8.2 节 |
| 流程有明确分支、暂停和恢复要求 | 状态管理与图编排 | 让缺少版本信息的任务暂停，补充信息后继续 | 资料篇第 8.1 节及 Java 编排资料 |
| 一个任务确实需要独立分工 | 多 Agent | 拆出一个职责明确的子任务，比较收益与额外成本 | 资料篇中的进阶项目与协作资料 |

RAG 可以作为固定检索流程，也可以成为 Agent 使用的工具；保存历史不等于模型下次自动记住，仍需要应用选择信息放入上下文。MCP 负责接入，Skills 提供任务知识，实际权限仍在执行入口检查。这些区别在入门文章第 2 节有展开说明。

权限、会话隔离和运行记录应随着能力增加继续检查。如果将来加入创建工单等写操作，还要补业务状态校验、幂等、审计与失败补偿；请求超时后先确认执行结果，不能直接重复创建，也不要跨多轮模型调用长期持有事务。

**这一阶段完成的标志**：挑一个明确的问题，记录改动前后的结果。例如接入一个 MCP 文档工具后，原有权限和超时用例仍通过；加入记忆后，不同用户的数据互不串用。其他能力先完成概念辨析，需要时再补实验，不以接入工具数量判断进度。

## 4、阶段 5：把资料助手做成完整项目

前面验证了一个个机制，现在把它们放回用户的一次完整任务中。第一版可以仍然只有资料查询，但要说明用户从哪里提问、能够访问哪些资料、如何查看引用、失败后怎样继续。根据使用方式选择控制台或简单 Web 入口即可。

这一阶段重点检查使用过程。换一个没有参与开发的人，按照说明准备配置、启动程序、提出问题，是否能够得到可核对的答案？更换用户、增加文档或制造工具故障后，行为是否仍符合预期？

| 交付物 | 需要说清什么 |
|---|---|
| 使用说明 | 运行条件、配置方式、支持的任务和不支持的范围 |
| 工具与数据边界 | 用户身份从哪里来，哪些文档可访问，怎样检查权限 |
| 验收记录 | 输入、预期、实际结果、引用依据，以及仍未解决的问题 |
| 运行记录 | 一次任务关联的模型调用、工具调用、耗时与停止原因，敏感信息脱敏 |

资料篇第 3 节的项目可以提供应用方向，第 8 节的工程文章用于补具体问题。如果想尝试多 Agent，可以把“核对引用”拆成独立职责，再与单 Agent 版本比较。只有在结果质量、上下文隔离或分工上出现明确收益时，才保留额外编排。

**这一阶段完成的标志**：他人能够按说明运行并完成约定任务，失败时能够知道原因和下一步。原型验收通过只证明当前范围内的行为，生产使用还需结合部署环境、真实数据与运行要求继续验证。

## 5、阶段 6：研究 Harness 与工程化

当你已经做过完整任务，工具执行、状态管理、上下文组织、错误恢复和观测记录就不再是陌生名词。这些支撑模型持续完成任务的机制，可以放在 Harness 的视角下一起研究。

先带着一个实际问题读源码，例如“任务中断后怎样继续”“重复工具请求怎样识别”或“上下文压缩后怎样保留关键依据”。沿着“请求进入 → 构造上下文 → 请求模型 → 分发工具 → 回填结果 → 停止”追一条执行链，记录权限检查、状态保存和异常处理的位置。

| 仓库内的入口 | 适合带着什么问题阅读 |
|---|---|
| [AgentScope Java](../agentscope/README.md) | 单 Agent、工具与会话在 Java 项目中如何组织 |
| [Pi Agent](../pi-agent/README.md) | 循环、会话和上下文处理分别由哪些部分负责 |
| [DeepSeek Harness](../deepseek-harness/README.md) | 模型之外的执行、状态与扩展能力怎样组合 |

记录 commit 或 tag，具体 API 和运行要求与所选版本核对。只阅读过的路径注明是源码分析；真正执行过的路径保留输入和结果。可以先用一个隔离的练习仓库体验编码类 Agent，再研究一次工具失败或任务恢复，不必第一遍就部署整套平台。

回到自己的资料助手，只迁入一个有依据的改进，例如恢复未完成任务，或把耗时定位到某次模型与工具调用。用原有用例检查结果，再比较调用次数、耗时和人工介入情况。

**这一阶段完成的标志**：能够用代码位置和运行记录解释一项设计取舍，并证明自己的改进解决了什么问题。生产运行中的监控、容量、成本和回滚继续按项目需求完善。

## 6、资料怎样读，才不会越读越散

第一轮给自己保留一套主教材、一个 Java 框架和一个练习任务。本文与入门文章帮助建立路线，Hello-Agents 用来补概念，官方文档用来核对实现。资料篇中的其他文章，带着当前问题查即可。

喜欢视频，可以从资料篇第 7 节选与当前框架对应的课程。看完一个示例，合上视频自己写一遍，再改一个条件，例如让工具返回“没有权限”或让文档缺一段。能够解释变化后的行为，比记住视频里的方法名更有用。

读 Python、TypeScript 示例时，先找输入、状态、工具执行和返回结果。理解这些职责后，再对应到 Java 的方法与对象。需要运行原项目时，再补相关语言和环境，不必把掌握所有语言作为学习 Agent 的前提。

每次学习可以留一份很短的记录：

| 记录项 | 内容 |
|---|---|
| 这次的问题 | 例如“为什么读取接口说明后没有继续查公共约定” |
| 依据 | 所读资料、章节、日期、代码版本 |
| 实验 | 输入、预期、实际结果和关键调用记录 |
| 结论 | 已经验证什么，什么仍是推断，下一次改什么 |

复习时先回答入门文章第 6 节的小测试，再看参考答案。遇到不确定的问题，回到文档和实验核对，避免把题库中的简短答案当成通用规则。

## 7、现在就可以开始的练习

先准备三份小文档，用一个 Java 模型调用示例解释其中的参数。还没有模型调用经验，就从阶段 0 完成多轮输入；已经会调用模型，就读 [什么是 Agent](01-what-is-agent-humanizer.md) 第 1～3 节，用自己的话写出资料助手的一次执行过程。

然后列出两个工具的输入、返回值和访问限制，写三道验收题：正常查询、资料缺失、越权读取。选择顺序学习或先做原型的路径，把这组材料和用例一直带到后续阶段；出现问题就留下记录，作为下一次学习的起点。

能够解释“查了什么、依据在哪里、为什么继续、为什么停止”，并用用例验证这些判断，就可以沿着真实问题继续深入了。
