````markdown
## 失败、盲区与排错

### 只改一个条件时，程序为什么会退出

`SamplingLab` 与 `EvidenceCheckLab` 的 `main(String[] args)` 都标注「args 未使用」：输入、观察文字、断言和预期错误码都写在源码里。下面是对**源文件临时副本**只改一处后的实跑结果（临时目录 `%TEMP%/prompt-lab-review/`，未写入仓库）：

| 改动（对应本文「继续练习」的建议） | 实际结果 | 原因 |
|---|---|---|
| top-p 阈值 `0.8 → 0.95` | `AssertionError: 保留达到阈值的最小前缀，并重新归一化`，退出码 1 | 断言要求 `C` 的概率为 0，阈值 0.95 时三个候选都会被保留 |
| `logits {2,1,0} → {0,0,0}` | `AssertionError: 降低温度提高 A 的概率…`，退出码 1 | 三项概率恒为 `0.3333`，温度不再改变分布 |
| 候选日期与时区同时改错 | `AssertionError: 预期 [DATE]，实际 [DATE, TIMEZONE]`，退出码 1 | 用例里手写的 `expected` 没有同步 |

前两种情况下，程序**还会打印与新条件矛盾的旧文字**（仍写「top-p=0.8」「阈值=0.8000」「温度越低，分配给 A 的概率越集中」）。所以目前安全的练习方式是：先把源文件复制一份，只改一处，**同时同步该处的预期与观察文字**，再运行；不要只改自变量，也不要把进程崩溃理解成算法错误。若要让「只改一个条件」真正可行，需要把参数做成命令行选项、把断言改成由输入动态推导的相对关系，并把观察文字改成由实际结果生成。

### 核验器会放过什么

`verify` 只比较地点、日期、时区、来源、概率五个字段，`Facts` 里没有自然语言字段。对原 `verify` 的两次调用（同样是临时副本）：

```text
候选自然语言：明天降水概率 0%，确定不用带伞；来源：高德地图（本次其实没有查询）
字段与证据完全一致时的错误码：[]          ← 接受
证据与候选一起被伪造时的错误码：[]        ← 接受
```

也就是说：文字把 `null` 说成 0%、来源标签只是字符串比对、字段全对但建议毫无依据，这些**都不会**被拒绝。12 个案例全是「该拒绝的被拒绝」，没有一个演示「本该拒绝却被接受」。读到「核验接受候选」时，应理解为「本实验覆盖的字段检查通过」，而不是「答案可信」。

### 常见环境问题

| 现象 | 处理 |
|---|---|
| 控制台中文乱码 | 按本文命令带上 `-Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8`；本文命令按 Windows 终端写法给出，其他终端需自行调整 quoting |
| 找不到检查类 | 协议检查类在 `src/test`，必须先 `mvn -q -DskipTests test-compile …`，且类路径要含 `target/test-classes`；正文 5.3.2 的 `$labClasspath` **不能**直接复用到这里 |
| 没有 `DEEPSEEK_API_KEY` | 只能完成 3-1、3-2、本机协议检查与离线回放；`chat` / `tools` / `compare` 会在请求前被拒绝，属预期行为 |
| 线上 `429` / `401` / 超时 | 程序不自动重试，`compare` 会保留已执行项并停止，不要把未运行的方案算进成功率 |
````

**理由**：这是「不完善」中最实质的一条——README 推荐的练习会崩却无警告，且只展示核验器抓得到的东西。把反例与排错写进讲义，比再加一段边界声明更能形成判断力。

````markdown
本文件第 75 行之后的 `chat` / `tools` / `compare` 都需要 Key 和 Maven；跳过它们不影响前两个离线实验的完整性。**唯一能看到「改一句提示词 → 输出不同」的环节仍在线上**，这也是目前这套配套最大的门槛，正文与配套资料正在补一条零 Key 的对照路径。
````

**理由**：75 行之后约 45% 篇幅对无 Key 读者不可执行，原文没有给出任何替代路线；而 `three-model-calls` 这个离线资源在 README 里出现 0 次。

## 补丁的天花板（必须说清楚）

文档补丁能解决「预测无记录位」「答案同屏」「练习会崩却没警告」「零 Key 无路线」「验证日志被误读」，但**不能**解决下面三件事，它们需要改 Java 程序：

1. **答案延迟可见**：P3 的 `<details>` 只是文档层缓解，程序仍是一次运行把输入、结果、解释全打印。彻底方案是给两个离线程序加 `--reveal`。
2. **自变量可自由操作**：P6 只是把「会崩」写清楚，程序 `args` 仍未使用、断言仍硬编码。彻底方案是参数化 + 断言改为动态相对关系。
3. **对照实验可见差异**：P4-c 只是诚实标注未实测。要看到差异，需要 `compare` 输出并排 diff、默认多跑一个未放进示例的用例、并存一份实测报告快照。

也就是说：**贴完这份补丁清单，README 会变成一份合格的运行手册 + 实验讲义，但三个实验本身仍是「带断言的演示脚本」。** 程序侧的改造建议见 `reviews/2026-11-07-LABS-DEEP-REVIEW.md` 第六节。
