## 3. 五个工程职责，落到同一个资料助手

本书 1.2 节的工程视角可用于检查系统缺了什么。下面是本教程的 Java 练习映射，不要求新建五个类或模块。

| 职责 | 只读资料助手中的具体行为 | 如何验证 |
|---|---|---|
| 上下文 | 提供问题、可用工具及实际返回的证据 | 缺少文档正文时，不得声称读过内容 |
| 工具 | 执行 search_notes 和 read_note | 调用 ID 能关联真实结果 |
| 约束 | 只接受允许的文档 ID，限制长度与步数 | 非白名单 ID 在执行端被拒绝 |
| 验证 | 检查引用是否存在并支持回答 | 给一个存在但不支持结论的引用，应判失败 |
| 纠正 | 对可恢复的只读错误有限重试，失败后说明未完成 | 持续错误不能变成无限调用 |

“Agent = 模型 + Harness”和“模型 + 上下文 + 工具”是不同层次的说明，不是两个互斥定义。现有离线模拟器只覆盖部分控制流，不能因此声称具备完整生产级 Harness。

## 4. 四个不依赖付费模型的练习

以下为本教材设计，不是书中实验的逐字复刻；纸上完成只能证明理解和设计，不能证明真实模型行为。

### A. 保存过，不等于这轮看得见

准备三条虚构记录：第 1 轮限定只读；第 2 轮列出文档 A；第 3 轮发现 A 已过期。保存完整记录，然后另写一份供下一轮使用的摘要。

验收：从摘要能否知道只读限制、A 已过期及原因？如果只保存“查过文档 A”，应判失败。继续追问：应用界面能翻到原记录，为什么仍不能证明模型收到它？

### B. 缓存不是把答案存起来

在纸上比较两组输入：固定说明 + 历史 + 新问题；每次改变开头时间戳 + 历史 + 新问题。标出每组可能复用的相同前缀。

验收：能说明 KV Cache 是计算状态，持久记忆是外部保存的信息；前缀更稳定只是创造复用条件，不保证缓存命中或固定折扣。权限变更、事实纠错必须及时更新，不能为保缓存保留失效规则。

联网后再补测：按 Provider 实际计费字段分别记录普通输入、缓存读取、缓存写入（如有）、输出及工具费用，不重复计算；再结合成功率比较总成本。具体规则查 [官方缓存文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)，本课不提供固定价格。

### C. 工具契约比工具数量更值得先改

旧说明只有“搜索资料”。改成：从三条指定学习笔记中按名称匹配，关键词非空且不超过 80 字符；不读取正文；返回文档 ID 与标题；无匹配和执行错误分开返回。

验收：分别写一个应调用、一个不适用、一个非法参数的例子。补充参数保真要求：若实现会去除首尾空白，说明该行为；若读取文档 ID，不能悄悄替换成另一个 ID。将模型请求与实际执行参数对照，避免把输入转换问题误诊为模型问题。对应 v1.0 正文 101～102 页。

### D. 改进有没有收益，要有对照

沿用第 04 章十道题，保留原方案 A，仅改工具描述得到 B。固定允许资料、题目、模型和其他配置，比较成功题、失败原因、用量和耗时。

验收：B 修好某一道题却导致权限题失败，不能采用；只有十题时，不把一次小幅提升写成统计结论。另准备两道未参与调试的新题检查迁移，避免把提示词改成背答案。对应 v1.0 正文 163～164、174 页。

## 5. 哪些说法要保留边界

- **“每轮都完整重发历史”**适合解释一种基础实现，不是所有产品的必然行为。实际可能截断、摘要、检索部分记录，或由服务端维护会话。学习时检查本轮实际可见信息。
- **MCP 不要求工具定义全量常驻上下文。** 它规定能力交换，宿主决定怎样提供给模型；Skills 和 MCP 可以配合使用，不是必须二选一。参见 [MCP 官方架构说明](https://modelcontextprotocol.io/docs/learn/architecture)。
- **上下文压缩后表现变差只是一个可能原因。** 也可能是检索缺失、工具错误、过时记录或任务歧义。先看轨迹，不能仅凭感觉断言压缩或缓存失效。
- **一般教程中的 system/user 角色例子不能替代宿主的指令层级和权限规则。** 格式相似不等于信任等级相同。
- **沙箱降低影响范围，不保证所有操作都正确。** 不沿用文章中放开全部权限的个人习惯；本课仍保留只读范围和执行端校验。
- **固定 RAG 不必然低效，多 Agent 不必然更强。** 采用新机制前，先指出旧方案在同一批任务上的具体失败。书中的机制分析用于提出可验证假设，不等于所有模型上的定律。
