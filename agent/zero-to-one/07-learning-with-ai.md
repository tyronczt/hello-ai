# 07｜用 AI 学 Agent：从看懂到独立解释

[返回入口](README.md) · [学习计划](04-study-plan.md) · [自测题](06-self-check.md)

> 更新：2026-09-14。参考小山学堂“AI 教我学习”的五个公开课节，改写为 Javaer 的学习练习。以下案例、时间安排和验收规则由本教材设计，未经过学习效果实验；不依赖任何业务项目。

## 1. 先写自己的起点，再选课

假设你会 Spring Boot，每周只有四小时，希望做一个只读资料助手。如果只让 AI 推荐 Agent 技术栈，它可能安排好几个框架和数据库；这份清单即使列出的技术都存在，也未必能在你的时间里完成。

参考 [这个建议适合我吗](https://xueai.miyang.cn/slides/learn-1.html)：先补实际条件，再检查建议依赖的前提。将下面这张卡填好，选课时逐项对照，而不是照收整张路线图。

```text
已会：Java 集合、异常处理、HTTP / JSON；Spring Boot 基础。
尚不会：工具调用、Agent Loop、模型评测。
可用时间：每周四小时，每次一小时。
本阶段目标：解释一次工具调用，并实现一个只读资料查询练习。
当前条件：先做无 Key 离线练习；联网实验另行记录模型与预算。
验收：能说明工具失败、无匹配、循环超限分别如何处理。
```

请 AI 对每条建议标记“现在需要 / 后面再学 / 信息不足”，并说出它依据卡片里的哪项条件。不要把未说明的 Python 基础、云账户或 GPU 当作你已经具备的条件。

## 2. 每节课从一个问题开始

参考 [按我的情况讲清楚](https://xueai.miyang.cn/slides/learn-3.html) 的提问结构，把已掌握内容、应用目标和验收写进请求。本课可直接使用：

```text
我会 Java 方法调用、参数校验和异常处理，正在学 Agent 工具调用。
请用“从三条学习笔记中查找 RAG”解释一次模型请求与工具执行。
先展示一段 CALL / RESULT / FINAL 轨迹，说明每一步由谁完成。
请特别区分：模型生成调用参数、Java 方法执行、任务正确完成。
然后只出一道改变输入条件的题；先等我回答，不给参考答案。
如果讲到某个框架 API，请附官方页面和适用版本；不确定就标注。
```

例子要落到正在练习的工具上。今天研究参数错误，就别同时要求 AI 讲完多 Agent 和长期记忆。AI 给出的 API 或评价仍需要用文档和运行结果核对。

## 3. 用 Java 类比，但标出哪里不一样

参考 [用熟悉的东西打比方](https://xueai.miyang.cn/slides/learn-4.html)。下面是本课程的 Java 对照，不是要求各框架必须按此实现。

| Agent 概念 | 可借用的 Java 经验 | 类比到哪里要停 |
|---|---|---|
| 工具定义 | 方法名、参数类型和用途说明 | 模型生成的参数不受 Java 编译器保证，仍需运行时校验 |
| 工具执行 | 调用一个受控 Service 方法 | 模型提出调用不等于获得业务权限 |
| Agent Loop | 循环里根据返回结果选择下一步 | 真实模型的下一步并非固定分支，必须限制步数和耗时 |
| 会话状态 | 按会话 ID 隔离的数据 | 不能把全部用户历史塞进一个 Spring 单例可变字段 |
| RAG | 查询数据，再组织返回内容 | 搜到相似文本，不等于文本支持答案中的每个结论 |

闭卷任务：任选一行，先说相同点，再给一个“照搬这个类比会出错”的例子。只有会背左列名词不算通过。

## 4. 一次回答一道题，暴露卡住的位置

参考 [一次只问一个问题](https://xueai.miyang.cn/slides/learn-5.html)。把 AI 当作提问者，让它根据你的答案决定补哪里。

**先自己完成下面这题，再让 AI 核对：**

```text
CALL search_notes(query="Kubernetes")
RESULT ok=true, text=NO_MATCH
FINAL 我已经确认：互联网没有 Kubernetes 学习资料。
```

问题：哪一部分超出了证据范围？你会怎样改写最终回答？

给 AI 的辅导要求：先检查我有没有区分执行成功与检索有结果；如果我只说“模型幻觉”，追问当前工具到底搜索了哪些资料。不要一次给出所有答案。需要提示才提示，并在记录里注明我用过提示。

完成后做迁移：只把工具结果改成 `ok=false, text=TIMEOUT`，其余不变。重新解释能否得出同样结论。这个新输入是教学假设，不是离线模拟器已有的网络超时实现。

## 5. 合上资料再验收

参考 [合上材料，让 AI 考我一次](https://xueai.miyang.cn/slides/learn-15.html)：先独立作答，再看反馈。源页面的演示比例不能当作你个人的记忆提升数据。

每次一小时可以这样用：

| 时间 | 动作 | 留下的东西 |
|---|---|---|
| 5 分钟 | 闭卷解释上次一个概念 | 原始答案，不先润色 |
| 15 分钟 | 学一个小节 | 一个待验证问题 |
| 25 分钟 | 预测输出，再运行或纸上模拟 | 预期与实际差异 |
| 10 分钟 | 回答一道换条件的新题 | 答案、证据、是否用提示 |
| 5 分钟 | 记录错误和下次复习 | 只写一个待补点 |

这是学习安排建议。下次学习开始时复测上次错题，周末换一个场景再问；答不出就补练，不追求固定天数完成。

**学习状态只记四种：**未尝试、借助提示完成、独立完成、换场景仍能完成。阅读结束不自动变为“独立完成”，AI 的表扬也不能替代证据。

## 6. 今天就完成的一次练习

打开 [离线 Java 实验](02-agent-loop-lab.md)，只做下面这组动作：

1. 不运行代码，预测默认查询、无匹配和空参数的三种结果。
2. 执行实验命令，将自己的预测与输出对照。
3. 合上代码，解释为什么 `DONE` 不代表事实正确。
4. 让 AI 只问一道新题，例如工具持续等待时，最大步数为什么不够。
5. 保存原始错误答案、修正理由和下一次闭卷复测结果。

```text
本次问题：
闭卷原答：
我预测的行为：
实际证据：文档章节 / 命令输出 / 工具返回
错误位置：概念 / 条件 / 参数 / 执行 / 证据范围
是否看过答案或使用提示：
修正后的解释：
学习状态：未尝试 / 借助提示完成 / 独立完成 / 换场景仍能完成
下次复测题：
```

AI 适合帮你出题、指出矛盾、追问依据；遇到版本或实现争议，回到对应源码、官方文档和可复现输出。自测题见第 06 章，尽量只向 AI 提供题目，答完再打开参考答案。
